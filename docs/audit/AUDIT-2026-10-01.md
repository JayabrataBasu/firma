## 4. Code vs manual, and silent defaults

Divergences:

- **F03. `NONE` focus repeats the previous action without an admissibility
  check.** `select()` returns `prev_action` directly (`decision/src/lib.rs:296-303`).
  The market rule then silently does nothing if the precondition fails
  (`action-market/src/lib.rs:283-286`, "Defensive … Silent no-op"), but
  `constrain` still appends the selected index to the action window
  (`constraint/src/phase_rules.rs:143-157`). In `cfg_arm_b_satisficing`,
  45 of 47 `NONE` decisions (44 `produce_regulated`, 1 `produce_ordinary`)
  produced no action delta, yet were recorded in `W` and counted toward `u`
  and toward the realised-action distribution. The five compliance deaths in
  that run (agents 4–7 at tick 47, agent 3 at tick 49) are the agents with
  those entries. Manual §12.3 says only "repeat previous action"; §11.4's
  admissibility is not applied to it.
- **F07. Legitimacy default differs between decide and act.**
  `decision/src/lib.rs:393` reads `LEGITIMACY` with `unwrap_or(1.0)`;
  `action-shaping/src/lib.rs:279` uses `unwrap_or(0.0)`;
  `constraint/src/phase_rules.rs:343` and `analysis/reconstruct.rs:248` use
  `1.0`. ADR-0047 states `p_success` in the lookahead is "the exact function
  `action.shaping.rdt_standard` calls at commitment, with the exact same
  `legitimacy` input". That holds only when the config seeds `legitimacy`
  (every sanity config does). Unseeded, the firm plans with λ = 1 and the
  draw uses λ = 0.
- **§11.4 admissibility** ("immediate effect does not violate a hard
  constraint") is implemented as preconditions plus the `scope` gate only.
  Covered by ADR-0021 (lines 99-100), so documented, not a defect.
- **Aspiration seeding.** `AspirationUpdate` (`decision/src/lib.rs:1334-1349`)
  seeds an absent `A_j` with the first non-zero `v_j` (a zero delta is
  skipped, so the field stays absent). The manual gives the update rule but
  no initial value. Not found in any ADR.
- **Plugin identity (F09).** `version()` is `1.0.0` and
  `catalog::CONTENT_HASH` is the literal `"phase2s3-decision-v1"`
  (`decision/src/lib.rs:50-53,131`), unchanged since `9c49c34` although
  `git diff 9c49c34 c5eb8cd` shows +431/−19 lines in that file (ADR-0047–0049).
  ADR-0047 calls its own change "MINOR". Content hashes are hand-typed
  labels in every plugin, so a manifest cannot distinguish pre- and

## 8. Run-safety

- **F06. Nothing in code prevents a run on seeds 1–200.**
  `derive_seeds(n)` returns `(n,n,n,n)` (`spec.py:114-142`);
  `ExperimentSpec.jobs()` always enumerates `1..=num_replicates`
  (`spec.py:421-432`); `build_narrowed_e1_spec` defaults to
  `num_replicates = 200` (`spec.py:474`); `run_experiment`
  (`runner.py:382-444`) has no confirmation, dry-run or filed-hash check; the
  CLI accepts any seeds. Calling `run_experiment(build_narrowed_e1_spec(t), …)`
  with any template executes the registered seed range. The only protection
  today is that Arm B's magnitudes are placeholder strings and five Arm C
  cells raise `KeyError` (F05). `prereg.check_seed_range` inspects runs after
  the fact.
- There is no way to give a later filing a different range (`first_replicate`
  is not implemented — ADR-0053's own "known limitation").
- **OQ-14 is not enforced anywhere.** `_add_pin_intervention`
  (`runner.py:78-103`) pins every agent in the template; it only rejects an
  empty agent list. No check in `spec.py`, `runner.py`, the CLI or the
  kernel requires one firm per Arm-A job.

## 9. Analysis pipeline

- **Known-answer tests exist.** `python/tests/test_stats.py` plants effects
  and checks verdicts for H1a/H1b (incl. sign flip via `outcome_direction`
  and centering), H1c (inverted U, monotone, U), H2 (supported / falsified /
  inconclusive), H4 (crossover / none / all censored), BH. 30 tests pass.
- **F02. Seed-invariant data produce a "supported" verdict with a
  zero-width CI.** A frame in which every seed has the identical outcome per
  cell and planted effects of `1e-6` gives
  `H1a supported, est 1.0e-06, CI (1.0e-06, 1.0e-06), failed 0` and
  `dissociation holds: True` (40 resamples). `_require_variation` checks the
  outcome column overall, not variation across seeds. With F01 this is the
  realistic input for any cell where shaping is never committed.
- **F04 (suspected). Arm A as built may not identify H1a/H1b.** Read from
  `decision/src/lib.rs:994-1001` and `runner.py:104-134`: (a) pinned `ς_1`
  takes values in `[0, 1]` and is compared with the integer change in
  liquid capital, so the four non-zero levels give the same test `Δ ≥ 1`;
  (b) at `h ∈ {0.02, 0.05, 0.10}` the focus is `SURVIVAL` and `ς` is not
  read at all; (c) in `SURVIVAL` the lookahead margin is the firm's real
  margin, compared with the pinned `h_t`; (d) `w_eff` depends on `h` only,
  so the `search_width` DV cannot respond to `ς` except through the
  `NONE`/`GOAL` switch. Not run (no registered template exists).
- **`ΔH_rep` is not computable** (OQ-20 item 8): no fork job in the runner,
  no per-run `H_rep`/R2/R3/N1/N2 exposed through `_native`. For Arm A, which
  has no shock, the manual's "no-shock fork" (§14.6) is not defined by any
  document found.
- OQ-20 items 1–7 remain open choices; `centers` has no default
  (`stats.py:352`), which is the safe state.
- `analyse_h3` raises `NotImplementedError` by design (ADR-0051).
